# Recipe Import Pipeline — сервер

Реализация `Recipe_Import_Pipeline_Spec.md` на FastAPI. Принимает ссылку на
YouTube-видео, извлекает рецепт (субтитры → Whisper → анализ кадров, по
убыванию приоритета) и структурирует его в JSON, готовый к прямому импорту
в PWA «ПП Рецепты».

Все AI-шаги (транскрипция, разбор кадров, структурирование) идут через
**Groq API**.

## Запуск локально

```bash
cd server
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и вписать GROQ_API_KEY
uvicorn app.main:app --host 127.0.0.1 --port 8099
```

Нужны системные `yt-dlp` и `ffmpeg` (например, `brew install yt-dlp ffmpeg`).
Если в PATH/venv есть свой `yt-dlp` — `app/ytdlp_tools.py` намеренно
предпочитает `/opt/homebrew/bin/yt-dlp` или `/usr/local/bin/yt-dlp`, чтобы не
подхватить случайно устаревшую pip-версию.

В PWA (Настройки → «Импорт из видео») укажите адрес сервера, например
`http://localhost:8099`.

## Защита ключа Groq (`app/ratelimit.py`)

По просьбе — встроена защита от шатдауна ключа при превышении лимитов:

- скользящее окно **RPM** (`GROQ_RPM_LIMIT`, по умолчанию 20/мин) — запросы
  просто ждут своей очереди, а не падают;
- дневной **бюджет запросов** (`GROQ_RPD_LIMIT`, по умолчанию 300/день),
  персистентный на диске (`groq_usage.json`) — переживает рестарт;
- backoff с уважением `Retry-After` на 429 и экспоненциальный на 5xx
  (`GROQ_MAX_RETRIES` попыток);
- задания обрабатываются **строго последовательно** (одна in-memory очередь) —
  это само по себе исключает параллельный залп запросов к Groq;
- кэш по `video_id` (SQLite, `cache.db`) — один и тот же ролик никогда не
  прогоняется через Groq дважды.

## API

```
POST /import-recipe          { "url": "..." }  → { "job_id", "video_id", "cached" }
                              либо сразу { "status": "ok", ... }, если video_id уже в кэше
GET  /import-recipe/{job_id} → { "status": "pending|processing|done|error", "step", "result", "error" }
GET  /health                 → { "status": "ok", "groq_requests_remaining_today" }
```

## Деплой на свой VPS

1. Скопировать `server/` на VPS, поднять venv, `.env` с ключом.
2. Поставить `yt-dlp` и `ffmpeg` через системный пакетный менеджер.
3. Если YouTube начнёт требовать «Sign in to confirm you're not a bot»
   (см. раздел 5 спеки) — экспортировать cookies залогиненного аккаунта в
   netscape-формате и указать путь в `YTDLP_COOKIES_FILE`.
4. Запускать под systemd/supervisor: `uvicorn app.main:app --host 127.0.0.1 --port 8099`,
   а наружу пробрасывать через тот же реверс-прокси, что уже стоит перед OpenReel.
5. В PWA указать реальный адрес сервера в Настройках.

## Известные ограничения качества извлечения

Модель на шаге структурирования (`openai/gpt-oss-120b`) иногда:
- не может понять, что "порция" — это одна штука из целой партии (например,
  тесто на несколько блинов), и не пересчитывает `servings` — итоговое КБЖУ
  в таких случаях может быть завышено в разы. Проверяйте поле «Порций» на
  экране импорта перед сохранением, особенно при бейдже «Нужна проверка».
- при альтернативных ингредиентах в рецепте («куриный ИЛИ говяжий фарш»)
  добавляет оба варианта как отдельные строки — лишний просто удаляется
  крестиком на экране импорта.

Поэтому при `confidence: low` (бейдж «Нужна проверка») экран импорта всегда
даёт отредактировать граммовки, КБЖУ кастомных ингредиентов, число порций и
состав перед сохранением — рецепт не улетает в базу вслепую.
